# Backend — AI Privacy & Consent Analyzer

FastAPI backend implementing the Backend Developer role from the Team Role
Guide: auth, database, web scraping, ML hookup, PDF reports, and admin stats.

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # then edit DATABASE_URL / JWT_SECRET_KEY
```

You'll need a running PostgreSQL instance matching `DATABASE_URL` in `.env`.
Tables are auto-created on startup via `Base.metadata.create_all` (fine for
a class project; swap for Alembic migrations in a real production app).

## Run

```bash
uvicorn app.main:app --reload
```

Interactive API docs (Swagger, auto-generated by FastAPI): `http://localhost:8000/docs`

## Project structure

```
app/
  main.py            FastAPI app, router wiring, CORS, startup DB creation
  config.py          Settings loaded from .env
  database.py        SQLAlchemy engine/session
  models.py          users, scans, reports, activity_logs tables
  schemas.py         Pydantic request/response models (the API contract)
  auth.py            bcrypt hashing + JWT create/verify + get_current_user dependency
  scraper.py         Requests+BeautifulSoup (static) with Selenium fallback (JS pages)
  ml_client.py        Calls the ML module's analyze() — HTTP if ML_SERVICE_URL is
                      set, otherwise a local stub so backend works standalone
  pdf_generator.py   reportlab PDF report builder
  routers/
    auth_router.py     POST /auth/signup, POST /auth/login
    scan_router.py     POST /scan (runs scrape+ML as a background task)
    reports_router.py  GET /history, GET /reports/{id}, GET /reports/{id}/download
    admin_router.py    GET /admin/stats
```

## Endpoints (matches the Frontend's expected API contract)

| Method | Path                      | Auth | Description |
|--------|---------------------------|------|--------------|
| POST   | /auth/signup              | no   | Create account, returns JWT |
| POST   | /auth/login               | no   | Returns JWT |
| POST   | /scan                     | yes  | Kick off a scan (scrape + ML), returns `scan_id` |
| GET    | /history                  | yes  | List past scans for the logged-in user |
| GET    | /reports/{scan_id}        | yes  | Full report: score, summary, clauses, trackers, recommendations |
| GET    | /reports/{scan_id}/download | yes | Download the report as a PDF |
| GET    | /admin/stats              | admin| Total scans, total users, average score, top domains |
| GET    | /health                   | no   | Liveness check |

All authenticated endpoints expect `Authorization: Bearer <token>`.

## Connecting the real ML module

`app/ml_client.py` currently falls back to a **local stub** (`_local_stub_analyze`)
so the backend can be built and tested before the ML engineer's model is ready.
Once they hand off `analyze(policy_text) -> {...}`, either:

1. **Same process:** replace the stub's body with `from ml_module import analyze; return analyze(policy_text)`, or
2. **Separate microservice:** set `ML_SERVICE_URL` in `.env` and the client will
   POST to `{ML_SERVICE_URL}/analyze` instead — no other code changes needed.

The expected JSON shape either way:

```json
{
  "score": 72,
  "flagged_clauses": [{"category": "third-party sharing", "risk": "high", "text": "..."}],
  "summary": "Plain-English summary...",
  "trackers": [{"name": "Google Analytics", "domain": "google-analytics.com", "category": "analytics"}],
  "recommendations": ["Look for a data deletion request form."]
}
```

## Notes / follow-ups for the Integration Lead

- CORS is wide open (`allow_origins=["*"]`) for local dev — restrict to the
  real frontend origin before deploying.
- `is_admin` on `User` is a plain integer flag for simplicity; promote a user
  by setting it to `1` directly in the DB until an admin-management endpoint
  is needed.
- Dockerize with a `Dockerfile` + add this service to the project's
  `docker-compose.yml` alongside Postgres, Frontend, and the ML service.
